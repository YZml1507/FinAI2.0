## 2. 核心发现：A 路策略的真实病因（H5 / H5b / H5c）

**这些都不需要跑回测、不需要改代码**——纯 `plan_positions` 函数级复算。

### H5：市值加权 × 单票 2 万下限 × **无再分配** ⇒ 断崖式丢弃
```
权重分布            实际建仓     留存现金
等权 1:1:1:1:1        5 只        0
温和不均 3:2:2:1:1    3 只        34,000     ← 选 5 只，只建 3 只
头部集中 10:1:1:1:1   1 只        43,000     ← 选 5 只，只建 1 只
```
**触发量是 top-5 的市值离散度**（等权时零丢弃），⛔ 不是"小市值"本身。

### H5b：死价位带 `[151,199]`（等权 base=30000）
```
close=150 → 建 5 只（整手后 30000）✓
close=151 → 建 0 只（15100）⛔   close=199 → 建 0 只（19900）⛔
close=200 → 建 5 只（20000，恰触界）✓
```
- 占 20–300 区间 **17.4%** ⇒ 策略**无法持有中等价位（150–200 元）标的**
- ⚠️ **`max_price=300` 的意图与实际错位**：它防"整手失真"，而真正的失真区间 `[151,199]` **全在 300 之下**——该过滤器**没覆盖它想防的问题**
- 精确丢弃条件：`100·p·floor(base/(100p)) < 20000`

### H5c ⭐：死带随 NAV 退化的**正反馈螺旋**（迄今最强）
```
NAV=150,000 → base=30,000 → 死带 [151,199]   占 17.4%
NAV=130,000 → base=26,000 → 死带 [66,300]    占 43.8%
NAV=110,000 → base=22,000 → 死带 [28,300]    占 77.2%
NAV=100,000 → base=20,000 → 死带 [21,300]    占 97.9%
NAV= 90,000 → base=18,000 → 死带 [20,300]    占 100%   ← 完全失效
```
**越亏 ⇒ base 越小 ⇒ 死带越宽 ⇒ 能建的标的越少 ⇒ 现金越多 ⇒ 越难回本。**

| | 解释什么 |
|---|---|
| H5 | 某时点：权重离散 ⇒ 低权重标的被丢 |
| H5b | 某时点：价位落入死带 ⇒ 建不成 |
| **H5c** | **时间序列：NAV 退化 ⇒ 死带单调变宽 ⇒ 持仓持续下滑** |

**它能统一解释此前所有假设都解释不了的现象**：日均持仓 0.5–1.8 只 / 现金 65.4% / **后期比前期更低** / MDD 43.08%。
**临界点**：`base < 20,000` ⇒ 全价位丢弃；**15 万本金等效触发线 `NAV < 100,000`**。
**实际产物对照**：终值 108,421 ⇒ 死带 **81.1%**；谷值处 ∈ [81.1%, 100%]。
**根因**：`min_position_value` 是**常量**而 `base` 随 NAV **浮动** ⇒ **量纲失配**。

### ㊶：`default_positions` 与 `target_count` 隐性双口径
```
实际 N = min(len(signals), target_count)，其中 len(signals) ≤ default_positions
⇒ default_positions 是隐性上限，且不在 PortfolioConfig 里（住在 candidates.py:205）
```
- **危险**：决定 H5c 临界线的参数**不在组合配置类里** ⇒ 只看 `portfolio.py` 的人会算错
- **全仓无跨配置一致性校验**；若有人把 `default_positions` 抬到 8（意图"多持几只"）⇒ **触发恒失效**
- **一个"想多买"的改动会导致"完全买不了"**

## 6. 方法论沉淀

### 同一病的 15 层（每层都是「某个断言未被机器验证」）
```
①SKIP放行 ②INCONCLUSIVE放行 ③门禁类内部恒过 ④CLI退出码背离 ⑤runner未对齐
⑥文档硬编码漂移 ⑦单一事实源自身漂移 ⑧校验器正则不完整 ⑨口径混用
⑩修复模块静默兜底 ⑪门禁自己输出口径混用 ⑫契约↔实现签名漂移
⑬"承诺但未实现"的字段（ci_blocking）⑭治理机制未接线（adoption）
⑮"机制存在"≠"机制生效"（scheduled_audit 策略降级）
```

### ⭐ 本阶段的三个「机制自守」里程碑（从人肉审计转向机制自守）
1. **守卫测试首次自动抓到漂移**：常量 869 vs 收集数 870 ⇒ `test_baseline_constant_matches_collected_count` **报警并给出修法**（此前十几层全靠人撞）
2. **接线元测试落地**（`test_gate_wiring.py` 13 例）：让「建了机制没接线」**自动化暴露**
3. **门禁异常兜底 = FAIL**：「检查器坏了」不再等于「检查通过」

### 主理人在本阶段共犯 5 处错误（全部认领）
| # | 错误 | 发现方式 |
|---|---|---|
| 1 | adoption 机制未接线（批评过工程师，自己又犯） | **自己撞出** |
