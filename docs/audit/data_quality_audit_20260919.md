## 二、R8 告警逐条复核

### 告警 1：「R7 指数 CSV 行序降序，pct_chg 在降序下计算」

**复核结论：对本仓落盘 parquet 不成立（已自纠）。**

本仓 `index_H20955_total_return.parquet` / `index_H00922_total_return.parquet`
（2676 行，2014-01-02~2024-12-31）实测：

- 行序 = 升序（`file_row_order_ascending = true`）；
- stored `pct_chg` 与 close 升序重算 `pct_change()` 相关系数 = **1.0**；
- 无重复日期、close 无缺失。

R8 告警针对的是 R7 采集阶段的原始 CSV（未进入本仓），本仓落盘时已按 close
重算，无反序收益问题。H20955 全期 CAGR（close 口径）= 14.94%，含 2014 年
大牛市段；2015-2024 十年口径 9.24%，与 TASK_TRACKER 登记值一致。

## 三、坏值处置方案（513100）

按调研纪律「隔离坏值，禁止直接覆盖原始数据」：

1. **不动原始 parquet**（`data/etf_bars/sh.513100/*.parquet` 保持现状）；
2. 在数据质量台账登记坏值坐标：`sh.513100 / 2022-01-14 / factor 5.0019`；
3. 下游若消费 513100 后复权序列，必须按 NAV chain 修复或剔除
   2022-01-14 起的 hfq 段（R8 subB `nav_vs_bar_check.csv` 已给出对照）；
4. 当前回测引擎**不消费 etf_bars/factor**（grep 确认无引用），
   故无紧急污染风险；待未来 ETF 层立项时先行修复。

## 四、511990 factor NaN 处置

货币 ETF 无公司行动，factor 语义应为恒 1.0。当前全 NaN 属采集器
对「无 factor 列数据源」的默认填充。建议：下游读取 etf_bars 时统一
`factor = factor.fillna(1.0)`；不补写盘（避免改历史产物哈希）。
