# 数据接入规程（新数据源落库清单）

> 创建：2026-09-17 ｜ 定位：任何「要不要拉 X 数据 / 怎么接 X 数据」的统一
> 入口。拉数据是 **L3 动作**（SUCCESSION 分级）——先过 STRATEGY §5 的门，
> 再过本清单。写不出第 0 步的答案 = 不许拉。

## 第 0 步：瓶颈声明（⛔ 门禁）

在 TASK_TRACKER 写明：**针对哪个已确认瓶颈、预期改变哪个指标**。
先例对照：
- ✅ GC001 利率：空仓 38.3% 已实证（utilization-audit）→ 过；
- ⛔ 分钟数据：触发条件=「执行误差被证实为主瓶颈」（如 T+1 开盘价假设
  系统性失真），当前无证据 → 不许拉；
- ⛔ 487 池内因子挖掘：样本太小必出噪声 → 已封顶（STRATEGY 六节）。

## 第 1 步：可得性探针（小样本先验）

⛔ 禁止一次全量。先拉 1 个月 × 1 标的，验证：
- 字段口径（复权方式/时间戳时区/单位是元还是%）；
- 缺失模式（停牌日、节假日、接口限频 limit≤5000）；
- 与既有数据交叉验证（同一标的同一日，两源对账）。

历史坑位表（接入前必查）：
| 坑 | 出处 | 对策 |
|---|---|---|
| stock_basic 在线拉取不可复现（2595 vs 986） | universe_provider 事故 | 一律落权威缓存 `FNAI_STOCK_BASIC_CACHE` 模式 |
| 货币 ETF K 线无收益（价格钉 100） | etf_bars 实测 | 用万份收益/七日年化，禁用收盘价 |
| akshare 511880「7日年化」= 累计净值 134 | R6 调研 | 按 FundType/SYType 判别列语义 |
| 东财净值 1→100 面值切换 | R6 调研 | 相邻日变化>50% 置 0 重建链式净值 |
| GC001 长假断档（春节 14 日） | e6b 实证 | ffill≤16 自然日，超窗 raise |

## 第 2 步：落盘规范

- 目录：`data/<domain>/`（如 `data/rates/`），parquet 格式；
- **幂等原子写**：写 `.tmp` → rename（参照 `build_gc001_series.py`）；
- 构建脚本放 `scripts/build_<name>.py`，内含合理性断言（范围/唯一性/
  单调性），断言失败 = 不产出不静默；
- 登记 `data/signal_layers_manifest.json` 或同级清单（口径/覆盖区间/行数）。

## 第 3 步：接入与对账

- 实验/探针输入必须可钉死：文件路径进 params（如 `cash_yield_series`），
  ⛔ 不许运行时在线拉；
- ⚠️ **新数据会改 data_hash**：接入后所有对比实验必须用新 hash 同批重跑
  （参照 b-repro 重锚流程）；
- fail-closed：开关开了数据不在就 raise，不许静默降级；
- PIT：财务/事件类按 `pub_date`/`end_date` 对齐；价格 RAW 不复权。

## 第 4 步：登记

TASK_TRACKER 记：来源、口径、覆盖区间、行数、预期增益、实测指纹
（hash）。若数据最终没用上，也要记「已拉未用」及原因——防止后人重复拉。
