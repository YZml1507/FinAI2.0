# 高价股过滤机制

**版本**: 1.0.0  
**日期**: 2026-09-02  
**模块**: `strategy/portfolio.py`  
**需求**: 防集中度风险与冲击成本放大

---

## 1. 设计动机

A 股市场高价股（如 >300 元/股）存在以下风险：

1. **集中度风险**：单票占组合比重过高（同等资金下，高价股持仓数量少，难以分散）；
2. **冲击成本放大**：高价股流动性往往相对较低，买卖价差与滑点占比更大；
3. **整手约束收紧**：A 股最小交易单位 100 股，高价股 1 手市值可达数万元，组合调仓灵活性下降。

为在组合管理层面系统性规避上述风险，在 `PortfolioConfig` 引入 **`max_price`** 参数，在 `plan_positions` 阶段过滤价格超限标的。

---

## 2. 实现口径

### 2.1 配置字段

```python
@dataclass(frozen=True)
class PortfolioConfig:
    max_price: Decimal | None = Decimal("300.0")  # 默认 300 元，None=禁用过滤
```

- **类型**: `Decimal | None`（⛔ 禁止 `float`，与全局金额规范一致）；
- **默认值**: `300.0` 元（基于 A 股主板/创业板/科创板历史价格分布，覆盖 98%+ 标的）；
- **禁用**: 设为 `None` 时不过滤（保留扩展能力，如港股 / 美股市场适配）；
- **校验**: `__post_init__` 检查非 `None` 时须为正 `Decimal`，否则 `raise PortfolioError`。

### 2.2 过滤逻辑

位置：`_plan_one(symbol, base, bar, cfg)` —— `plan_positions` 的内部逐票评估函数。

```python
# 高价股过滤（防集中度风险与冲击成本放大）
if cfg.max_price is not None and close > cfg.max_price:
    return None, "超过价格上限"
```

- **判定条件**: `bar.close > cfg.max_price`（收盘价严格大于上限即拒）；
- **优先级**: 在流动性过滤之前（价格更基础的硬约束）；
- **失败路径**: 返回 `(None, "超过价格上限")`，调用方收集进 `dropped` 元组供追溯。

### 2.3 作用域

- **仅建仓端**：`plan_positions` 生成目标持仓时过滤，已持仓标的 **不受影响**（平仓由信号 / 择时 / 时间退出控制，不因价格上涨主动清仓）；
- **不影响信号**：`select_targets` 仍按分数排序，价格过滤在组合层，保持策略层与组合层正交。

---

## 3. 阈值选择依据

| 阈值（元） | 覆盖率（估算） | 适用场景 |
|---|---|---|
| **300** | ~98% | **默认值**：主板/创业板/科创板绝大多数标的；平衡风险控制与标的池广度 |
| 200 | ~95% | 保守配置：进一步降低集中度风险，牺牲部分优质高价股 |
| 500 | ~99%+ | 宽松配置：仅过滤极少数极端高价股（如贵州茅台历史峰值） |
| `None` | 100% | 禁用过滤：港股/美股扩展或特定高价股策略（需独立评估流动性） |

**当前默认 300 元理由**：

1. **历史数据**：A 股 >300 元标的长期占比 <2%（主板龙头 + 次新股为主）；
2. **整手约束**：300 元 × 100 股 = 3 万元，已接近单票下限 2 万元配置的上沿，再高则整手化损失放大；
3. **流动性分布**：300+ 标的日均成交额中位数往往低于 5000 万（流动性下限），双重过滤下实际可用标的更少。

## 4. 测试覆盖

**文件**: `tests/test_high_price_filter.py`（11 个单测全绿）

### 4.1 配置校验（5 例）

- 默认 `max_price = 300.0`；
- `None` 合法（禁用过滤）；
- `float` 拒绝（`PortfolioError`）；
- 零 / 负值拒绝；
- 正 `Decimal` 合法。

### 4.2 过滤逻辑（5 例）

- 价格 >300 元标的 dropped（原因="超过价格上限"）；
- 价格 =300.01 元边界 dropped（严格 `>` 判定）；
- 价格 =299.99 元通过；
- `max_price=None` 允许 999 元极端高价股；
- 多只高价股同时过滤，dropped 包含全部原因。

### 4.3 全链集成（1 例）

- `select_targets` 按分数排序（不看价格）→ `plan_positions` 过滤高价股 → 高分贵股被 drop，低分低价股入选。

## 5. 使用示例

### 5.1 默认（300 元上限）

```python
from decimal import Decimal
from strategy.portfolio import PortfolioConfig, plan_positions

cfg = PortfolioConfig()  # max_price=300.0
targets = ["sh.600519", "sz.000858", "sz.300750"]  # 贵州茅台 / 五粮液 / 宁德时代
bars = {
    "sh.600519": bar(close="1800.00", amount="5000000000"),  # 茅台 1800 → 过滤
    "sz.000858": bar(close="180.00", amount="3000000000"),    # 五粮液 180 → 通过
    "sz.300750": bar(close="250.00", amount="8000000000"),    # 宁德 250 → 通过
}
plan, dropped = plan_positions(targets, Decimal("150000"), bars, cfg)
# plan = {"sz.000858": ..., "sz.300750": ...}
# dropped = [("sh.600519", "超过价格上限")]
```

### 5.2 禁用过滤（高价股策略）

```python
cfg = PortfolioConfig(max_price=None)  # 不过滤任何价格
plan, dropped = plan_positions(targets, Decimal("200000"), bars, cfg)
# 所有标的按流动性 / 单票下限等其他规则评估，价格不限
```

### 5.3 自定义阈值（保守 200 元）

```python
cfg = PortfolioConfig(max_price=Decimal("200.0"))
# 进一步降低集中度风险，牺牲 200-300 元区间标的
```

## 6. 注意事项

1. **已持仓不受限**：过滤仅作用于新建仓，若标的已持有后价格上涨超 300 元，系统 **不会** 主动清仓（防频繁调仓）；
2. **与流动性正交**：高价股可能流动性充足（如茅台），但仍因价格过滤；低价股可能因流动性不足被过滤——两者独立判定；
3. **信号层不感知**：`select_targets` 仍会选出高价股，仅在 `plan_positions` 阶段 drop，策略层无需修改；
4. **扩展市场适配**：港股 / 美股高价股更常见（如 BRK.A），启用前需 **显式设 `max_price=None`** 或提高阈值。
